# Outlook Calendar

See also [[Calendar Providers]], [[Google Calendar]], [[Day Preview]], and [[code-notes]].

- The default source observes Outlook Web responses already loaded by the page. A small provider-declared capture starts at `document_start`, then hands its bounded queue to an optional Outlook parser injected through Chrome's scripting API. It does not make an additional calendar request or use a separate Microsoft Graph login.
- Initial events come from `startupdata.ashx` → `getCalendarView.Body.Items`. Only validated item IDs, titles, times, availability status, category names/colors, calendar names, and timezone data cross the isolated bridge.
- Later `service.svc` responses update the same cache by item ID. Request sequence (absolute high-res timestamp) prevents an older response from restoring a moved item.
- Outlook's blob `DataWorker` performs create/update/delete and later `GetCalendarView` calls. Early capture wraps `window.Worker` (provider flag `structuredWorkerCapture`), prepends a fetch/XHR relay to the original Blob, and passes the Trusted Types check by reusing a page policy that returns the blob URL unchanged, or by creating a duplicate of an allowed policy name. It fails open to the unwrapped worker.
- Delete requests carry the ID only in the request (`x-owa-urlpostdata` header); a successful delete-like response confirms it. `EventScope`: 0 single event, 1 this occurrence, 2 this and following, 3 whole series (request `EventId` is the clicked occurrence). `GetCalendarView` (RangeStart/RangeEnd + FolderId) is authoritative for its folder/range, but never removes records learned after the view request started.
- Outlook defers the actual delete request for its undo window. Adaptive DOM reconciliation (`structuredDomReconciliation`) hides structured events whose `data-calitemid` node vanished from an unchanged view (route + visible dates + viewport), adds DOM-only IDs, and trusts DOM times after 4 s of disagreement (immediately when worker capture is not active, or for IDs a successful `Update*Request` confirmed in the last 30 s; those also take the DOM title). The update response carries only the ID; the full item arrives 2–5 s later via `GetCalendarEvent`.
- Chrome's `sender.url` stays at the document's load URL after Outlook `pushState` routes (e.g. `/calendar/item/<id>` edit form); snapshots are validated against `sender.tab.url`, and URL mismatches are retryable.
- Outlook sends some offline mutations through a page worker. A fail-open, view-scoped overlay may temporarily suppress a structured ID only in the live source page after repeated settled `data-calitemid` observations; it never edits the canonical structured snapshot or the persisted compatibility feed.
- Suppression is bound to the top-frame Chrome `documentId`, source instance, route/date scope, selected-calendar state, structured folder count, structured revision, timezone, and monotonic observation/commit sequences. It is disabled when more than one Outlook tab is open.
- Mounted calendar options must exactly match the complete structured folder inventory. Folder names must be globally unique, then selection is mapped back to stable folder IDs; any mismatch fails open.
- Meetings and records with unknown `IsMeeting` state are never suppression candidates, so Outlook's “Hide declined events” filter cannot be mistaken for deletion.
- Current production evidence permits only the exact tested timed-lane profile: 1044×752 viewport, 703×494 surface, two ordinary non-overlapping single-day records of 30 and 150 minutes. Every other geometry/layout fails open. All-day suppression remains disabled until a bounded overflowing all-day fixture proves complete mounting.
- Outlook Windows timezone data is converted only through the matching response record's valid IANA timezone. Unknown or mismatched records fail to DOM capture instead of guessing from an unrelated offset.
- The shared Outlook appearance contract maps structured master-category presets to arc colors. Master category `Color` is the 0-based preset index (Red 0, Blue 7, Purple 8). Uncategorized structured events take the rendered color via the provider's `readEventColor`; the generic reader would pick the wrapper's gray border. The first known event category wins; otherwise `OOF` uses Outlook's away color.
- `[data-calitemid]` is a locale-independent fallback for title, time, appearance, and hover matching. Normal events use their computed event layer; a proven striped OOF layer uses `--freeBusyAwayColor`. DOM fallback does not infer category semantics when OOF and category styling overlap.
- Canonical Outlook events, a fail-open persisted display feed, and presence metadata use separate `calendarClockOutlook*` storage keys. A validated effective subset is delivered directly to the embedded clock and is not trusted across page or service-worker lifetimes.
- [[Day Preview]] uses the primary Fluent Today/Chevron toolbar and mounted `data-column-date` columns, never the mini-calendar month controls. Work Week stays active for weekdays; a weekend target switches through Outlook's locale-independent Day ribbon command because Work Week cannot mount that date.
